# Avoid repeating photographs on any one page

Editorial rule: **Never display the same photograph twice on a single rendered page**, including a crop, resized thumbnail, WebP conversion, or same image stored under a different filename. This applies to the homepage, all hubs, city/destination pages, tours, individual travel guides, related-guide cards, and hotel/attraction cards. It does not prohibit using the same photograph on different pages.

Fix repeated editorial photographs by selecting a genuinely different, relevant image from the owner's WordPress media archive (connected Google Drive /ChatGPT/2024, /2025, /2026) or a separately licensed project photo. Avoid using the same photo for both an area banner and a card below it. Keep working links and consistent photo credits, alt text, lazy loading, and local hosting; never replace a useful card with irrelevant imagery solely to meet uniqueness.

Current fixes: Attractions banner and Mount of Olives, homepage repeated city and destination cards, Tours guide/category overlap, city accommodation quick picks versus expanded area cards, and Hotels airport-arrival cards. Added photoIdentity/repeatedPhotos tests for key hubs, with normalization of WordPress size variants. All images from the owner's media archive remain subject to original licensing/attribution review.

Before publishing any subsequent page, check all images **as displayed together** (including hero, area labels, card grids, recommendations, related guides and responsive crops). The automatic check detects duplicate/size-variant filenames but cannot guarantee semantic or perceptual uniqueness for differently named copies; visual review is still required.
